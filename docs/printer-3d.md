# 3D 制作台使用与验收

宿主 0.2.3，插件 `community.printer-3d@1.2.0`。这是独立娱乐玩法，不连接真实直播间，不包含平台采集、支付和软件内交易。

## 使用

1. 执行 `devbox run desktop`（已配置原生依赖的 Windows 环境可执行 `pnpm tauri dev`）。
2. 在左侧“玩法”选择“3D 制作台 · 独立娱乐” **1.2.0** 并启用，点“工作台”即可查看实际制作画面；不会新开展示窗口。
3. 在“手动制作”填写昵称/文字、作品类型、事件和数量；在“规则演示台”选择测试观众并点击规则按钮。手动提交与模拟提交分别标注来源。
4. 在规则演示台批量导入自有 PNG/JPEG（单次最多 20 张），选择图像后制作；也可在“自有素材与帮助”读取已保存图片。图片经 Rust 解码、缩小、重编码后才可使用。
5. 要声音时，在工作台画面点击“启用本窗口声音”，在声音设置中取消静音；语音还需启用业务配置中的语音选项。没有可用本地语音时保留字幕。
6. 画面设置可即时调整；业务规则使用“保存并应用到新任务”。旧任务保留接收时的配置、份数和冻结分数。切换插件版本仍需清空在制和等待任务。
7. 直接拖动画面调整镜头、滚轮缩放，可保存最多 10 个命名镜头。画面随工作台可用空间和 DPR 调整，不再提供独立输出窗口尺寸。
8. 点击“生成规则 PNG”，在控制台检查预览，再选择位置保存。规则文案来自当前配置，不含平台图标与联系方式。

自动演示默认关闭，需显式开启。仅在无在制/等待任务、展示就绪且未暂停时生效，间隔 15–120 秒；重启后关闭。模拟内容不会当作真实平台送礼。重置演示只清理模拟任务/记录，保留手动数据。

## 数据与恢复

- 宿主维护唯一队列，容量按未完成份数计算，最多 100 份；事件数量乘规则份数后超限会整体拒绝。
- 默认优先排队不打断当前。明确选择“受控让位”时保留已完成份和冻结计划，未完成份重新制作，旧 epoch 的回调失效。
- 一份在完整打印和机械臂转运后回执；全部份数完成后任务才结束。成品之后的传送带移动不产生额外业务记录。
- 渲染实例丢失、WebGL context lost、系统长时间休眠会记录故障/中断。明确重试时已完成份不重复，分数不重抽。
- 仅支持当前 SQLite 检查点结构，不提供旧开发数据库迁移或回退兼容。遇到 `legacy_local` 等旧字段启动错误，按[开发数据目录与删库重置](development-data-reset.md)备份并重新初始化；文档列出各平台路径及 WAL/SHM 处理。
- 图片为插件摘要隔离的内容引用，不向插件暴露绝对路径或任意 URL。单次输入图片 8 MiB、最大 4096×4096，导入后最长边 512；每插件最多 200 张且 200 MiB。被任务、命令回执、配置或状态引用的图片不能删除。
- 历史最近 1000 条、每场命令回执最多 10000 条；运行检查点仍有 64 MiB 上限。任务、单元、回执、偏好另有事务一致的查询投影；图片二进制不进入 JSON 检查点。

## 采集与性能

实际画面在工作台内直接渲染，窗口及分栏大小决定显示尺寸。五档质量、六种抗锯齿和 24/30/60/90/120 FPS 为目标配置，实际以诊断为准；MSAA 按设备能力降级，内部渲染受 8,294,400 像素及 2×倍率预算限制。低帧率只降低内部超采样。


验证与截图见仓库内报告 `report/工作台内嵌玩法展示实施记录.md`。Windows WebView2、NSIS 冷安装、实际声音设备与语音、OBS/直播伴侣、高 DPI 及连续 30 分钟资源验收仍需目标机器执行。

## 1.2.0 桌面工作台

使用 liveboom 0.2.3 或更新的兼容宿主。在左侧“玩法”选择 3D 制作台 1.2.0，处理完当前及等待任务后显式启用。启用后点“工作台”进入布局；未上线阶段不保留旧操作台兼容。

正常窗口使用任务、预览和属性三个分区；可拖动分隔条，也可用键盘焦点与方向键调整。窄窗口通过“任务队列”“属性与工具”打开侧面板，Esc 返回。属性分为规则、画面、声音、演示、素材和记录；规则按条编辑。手动提交在预览下方，支持 Ctrl/Cmd+Enter。客户端工具栏可以恢复默认布局，设置页可以开启舒适字号。

工作台中央为实际渲染画面与唯一音频输出；OBS / 直播伴侣可采集当前客户端窗口，并按需裁剪画面区。缩放或切换导航不重置任务、相机和草稿。原作者署名与 MIT 许可证保留。
